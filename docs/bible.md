## 1. ДНК проекта

**Ядро:** Напряжённая оборона космической станции. Простая механика, высокое напряжение, мгновенное вовлечение.

**Манифест:**
> «Сделай просто, сделай напряжённо. Игрок должен чувствовать давление с первых секунд.»

**Правила:**
1. **Моментальное вовлечение** — нулевой онбординг, сразу бой
2. **Нарастающее напряжение** — каждая волна сложнее предыдущей
3. **Справедливая сложность** — смерть = ошибка игрока, а не рандома
4. **Зрелищность без цены** — эффекты не убивают FPS
5. **Яндекс игры — платформа** — всё под SDK

## 2. Концепция игры

### Ролевая модель
Игрок — **последний рубеж обороны**. Он не герой, он — охранник, который оказался в неправильном месте. Его задача — продержаться, а не спасти мир.

### Ключевые эмоции
- **Давление** — враги со всех сторон, мало места
- **Надежда** — между волнами шанс восстановиться
- **Триумф** — победа над боссом после напряжения

### Почему это работает
- Минимум механик (двигайся + стреляй + рывани)
- Максимум напряжения (волны + ограниченное здоровье)
- Быстрый цикл повторной игры (5 волн = 3-5 минут)

## 3. Игровые системы

### 3.1. Бой (Combat)
- **Автоприцел** — всегда стреляет в ближайшего врага
- **Урон — числовой**, не визуальный. HP врага скрыт от игрока
- **Отдача** — вспышка попадания, враг краснеет на 0.1с
- **Смерть врага** — анимация взрыва + партиклы

### 3.2. Волны (Wave System)
- **5 волн**, каждая с нарастающей сложностью
- **Warmup** — 10 секунд перед волной
- **Размер волны:** 5 + (waveNum × 4) врагов
- **Состав волн:** случайный из доступных типов

### 3.3. Враги (Enemies)
| Тип | Роль | Угроза |
|-----|------|--------|
| Бегун | Быстрая угроза | Сближается, наносит урон в ближнем бою |
| Стрелок | Подавление | Стреляет издалека |
| Танк | Цель высокой стоимости | Взрывается при смерти, AoE урон |
| Мини-босс | Мини-элита | Усиленный бегун, много HP |
| Босс | Финальная угроза | 3 фазы, разные атаки |

### 3.4. Улучшения (Upgrades)
- **6 типов**, стакаются (до 2-5 раз)
- **Рандом из 3** между волнами
- **Сила пропорциональна риску** — мало взял = сложнее

### 3.5. Движение игрока (Movement)
- **Свободное** — без привязки к сетке
- **Рывок** — быстрое уклонение (кулдаун 2.5с)
- **Без прыжков** — всё в 2D-плоскости с видом сверху

### 3.6. Окружение (Environment)
- **Станция** — арена 30×30, стены по краям
- **Освещение — кинематографичное** — много неонов, мрачно
- **Без интерактивных объектов** — только визуал

## 4. Прогрессия сложности

| Волна | Врагов | Новые типы | Особенности |
|-------|--------|------------|-------------|
| 1 | 5-9 | Бегуны, Стрелки | Знакомство |
| 2 | 9-13 | + Танки | Появляются цели с AoE |
| 3 | 13-17 | + Мини-босс | Стресс-тест |
| 4 | 17-21 | Все типы | Предфинал |
| 5 | 21-25 + Босс | Все типы | Финальная битва |

## 5. Производительность и ограничения

### 5.1. Технические лимиты
- **Pixel Ratio** ≤ 2
- **draw calls** < 150
- **Память** < 200MB
- **Размер бандла** < 5MB gzip
- **FPS** ≥ 30 на мобильных, ≥ 60 на десктопе

### 5.2. Триггеры деградации
| Условие | Действие |
|---------|----------|
| FPS < 30 более 3с | Снизить количество частиц на 50% |
| draw calls > 200 | Отключить тени |
| Память > 180MB | Принудительный GC через dispose() |

### 5.3. Тестовые устройства
- Desktop: средний GPU (GTX 1050)
- Mobile: iPhone 12, Xiaomi Redmi Note 10

## 6. Правила разработки

### 6.1. Архитектура
1. **Разделение ответственности** — каждый класс делает одно
2. **Композиция > Наследование** — враги собираются из частей
3. **State Machine** — GameState управляет переходами
4. **Event-driven** — системы общаются через события, а не напрямую

### 6.2. Качество кода
1. **Чистые функции** — где возможно, без сайд-эффектов
2. **Конфиг — данные** — вся балансная информация в config.js
3. **Нет магических чисел** — все константы именованы
4. **Комментарии — почему, не что** — объяснять мотивацию

### 6.3. Тесты
- Нет юнит-тестов (MVP прототип)
- **Ручное тестирование** — чеклист перед каждым билдом
- **Производительность** — Chrome DevTools Performance

## 8. Риск-менеджмент

| Риск | Вероятность | Влияние | Митигация |
|------|------------|---------|-----------|
| FPS падает при множестве врагов | Средняя | Высокая | Пул объектов, LOD |
| Yandex SDK меняет API | Низкая | Средняя | Обёртка для SDK |
| Баланс слишком лёгкий/сложный | Высокая | Средняя | Итеративная настройка |
| Конфликт версий Three.js | Низкая | Высокая | Фиксировать версию в lock |

## 9. Принципы принятия решений

### Конфликты решаются в пользу:
1. **Игрового опыта** — если фича не добавляет эмоций, она не нужна
2. **Производительности** — если фича убивает FPS, она не нужна
3. **Простоты** — если можно сделать проще, сделай проще
4. **Яндекс игр** — если фича ломает интеграцию, она не нужна
